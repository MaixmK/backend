# Лабораторна робота №4

## Тема
Розширені можливості Node.js-додатків: логування, завантаження файлів, моніторинг продуктивності.

## Мета роботи
Ознайомитися з розширеними можливостями серверних застосунків на базі Node.js: логуванням запитів і подій, завантаженням файлів на сервер та моніторингом продуктивності застосунку.

## Що було реалізовано у проєкті

### 1. Запуск базового сервера
У проєкті використовується Express-сервер у файлі `server.js`. Для перевірки роботи сервера реалізовано маршрут:

```http
GET /
```

Він повертає відповідь:

```json
{
  "message": "Backend працює"
}
```

### 2. Логування HTTP-запитів через Morgan
До `server.js` підключено бібліотеку `morgan`:

```js
app.use(morgan('combined'));
```

Після цього всі HTTP-запити відображаються у консолі: метод, адреса, статус відповіді та час виконання.

### 3. Файлове логування через Winston
У файлі `utils/logger.js` налаштовано Winston. Логи записуються у два файли:

- `app.log` — загальні інформаційні повідомлення;
- `error.log` — повідомлення про помилки.

Логер використовується для запису запуску сервера, запитів, помилок і результатів завантаження файлів.

### 4. Обробка помилок
У кінці `server.js` додано глобальний middleware для обробки помилок. Він записує помилки через Winston і повертає користувачу JSON-відповідь:

```json
{
  "message": "Текст помилки"
}
```

### 5. Завантаження одного файлу
Створено файл `routes/upload.routes.js`, у якому реалізовано маршрут:

```http
POST /upload
```

Для перевірки у Postman потрібно вибрати:

- Body;
- form-data;
- поле `file`;
- тип поля File;
- файл формату JPG, PNG або PDF.

### 6. Завантаження кількох файлів
Реалізовано маршрут:

```http
POST /upload-multiple
```

У Postman потрібно створити кілька полів з однаковою назвою `files` і вибрати декілька файлів. Максимальна кількість файлів — 5.

### 7. Валідація файлів
У Multer додано перевірку типів файлів. Дозволені формати:

- JPG;
- PNG;
- PDF.

Також встановлено обмеження розміру одного файлу — 5 MB.

Якщо користувач завантажує файл неправильного типу, сервер повертає помилку:

```json
{
  "message": "Дозволено завантажувати тільки JPG, PNG або PDF"
}
```

### 8. Моніторинг стану сервера
Додано маршрут:

```http
GET /status
```

Він повертає інформацію про стан сервера:

- статус;
- uptime;
- використання пам’яті;
- використання CPU.

Приклад відповіді:

```json
{
  "status": "OK",
  "uptime": 35.42,
  "memoryUsage": {},
  "cpuUsage": {}
}
```

### 9. Вимірювання часу відповіді
У `server.js` додано middleware, який фіксує час обробки кожного запиту. Результат записується у файл `app.log` у полі `responseTime`.

### 10. PM2
У `package.json` додано команди для запуску через PM2:

```bash
npm run pm2:start
npm run pm2:logs
npm run pm2:monit
npm run pm2:restart
npm run pm2:stop
```

## Команди для запуску

Встановлення залежностей:

```bash
npm install
```

Запуск сервера:

```bash
npm start
```

Запуск через PM2:

```bash
npm install -g pm2
npm run pm2:start
npm run pm2:monit
```

## Що потрібно показати під час захисту

1. Запуск сервера через `npm start`.
2. Перевірку `GET /`.
3. Перевірку `GET /status`.
4. Логи Morgan у консолі.
5. Файл `app.log`.
6. Файл `error.log` після помилки.
7. Завантаження одного файлу через `POST /upload`.
8. Завантаження кількох файлів через `POST /upload-multiple`.
9. Помилку при завантаженні неправильного формату файлу.
10. Запуск через PM2 та перегляд `pm2 list` або `pm2 monit`.

## Контрольні запитання

### 1. Що таке middleware у Node.js?
Middleware — це проміжна функція, яка виконується між отриманням запиту сервером і формуванням відповіді. Вона може перевіряти дані, логувати запити, обробляти файли, перевіряти авторизацію або передавати помилки далі.

### 2. Яка різниця між Morgan і Winston?
Morgan використовується переважно для автоматичного логування HTTP-запитів. Winston є більш універсальним логером, який дозволяє записувати події, помилки та іншу інформацію у файли з різними рівнями логування.

### 3. Як працює Multer?
Multer обробляє запити типу `multipart/form-data`, витягує файл із запиту, зберігає його на сервері та додає інформацію про файл у `req.file` або `req.files`.

### 4. Які метрики продуктивності важливі для серверів?
Основні метрики: час відповіді сервера, використання оперативної пам’яті, використання CPU, uptime та кількість помилок під час роботи.

### 5. Що таке uptime?
Uptime — це час безперервної роботи сервера або процесу з моменту його запуску.

## Висновок
У ході лабораторної роботи було розширено існуючий Node.js backend. До проєкту додано логування HTTP-запитів через Morgan, файлове логування через Winston, завантаження одного та кількох файлів за допомогою Multer, перевірку типу й розміру файлів, endpoint для моніторингу стану сервера та запуск через PM2. Завдяки цьому сервер став більш зручним для контролю, діагностики помилок і перевірки продуктивності.
